Git & GitHub 速通

从零到发布网站的实战笔记

2026 年 7 月 基于真实操作回顾
背景：本笔记源于一次真实操作——将一份行业分析报告通过 Git 推送到 GitHub，并用 GitHub Pages 发布为网站。每一步操作都拆解为「做了什么 + 为什么这样做 + 底层原理」。适合零基础对照学习。

起点：你要做什么

假设你有一堆写好的文件（报告、网页、代码），你想：

  1. 记录每次修改的历史，随时能回退到旧版本
  2. 把文件存到云端，换电脑也能继续工作
  3. 生成一个 URL，别人点开就能看

答案是：Git（版本控制）+ GitHub（远程托管）+ GitHub Pages（网站发布），三样东西串成一条链。

一、Git 和 GitHub 是两样东西

先建立最核心的概念区分：

GitGitHub
是什么你电脑上的一个软件（命令行工具）一个网站 (github.com)，微软旗下的公司
干什么记录文件版本——「时间机器」存放 Git 仓库 + 协作 + 部署
需要联网？不需要，完全离线可用需要，它是一个远程服务器
关系Git 管本地 → git push 推到 GitHub → 代码在云端 → 别人能访问
关键认知：你大部分时间在跟 Git 打交道（commit、查看历史、回退），只在需要同步或发布的时候才跟 GitHub 通信（push、pull、clone）。Git 是每天用的工具，GitHub 是最终的目的地。
所以 GitHub 只是「存代码的网盘」吗？

远超网盘。网盘只存最新版本，GitHub 存完整的历史记录——每次 commit 的快照都在。你可以：

  • 查看三年前的代码长什么样
  • 对比任意两个版本之间的差异（谁改了什么）
  • 多人同时改同一个项目而不会互相覆盖
  • 通过 Pull Request 做代码审查
  • 用 Issues 跟踪 Bug 和需求
  • 用 Actions 做自动化（测试、部署）

GitHub 不是网盘，是协作平台。网盘只是它最基础的功能。

二、git init — 造一台「时间机器」

git init

这行命令在当前文件夹里创建一个隐藏目录 .git。这个目录就是「时间机器」的核心——它会在后面记录你全部的版本历史。

操作前操作后
一个普通文件夹，改了文件没有痕迹文件夹变成「仓库 (Repository)」，每次修改都可以存档

.git 目录里有什么？（不用记，知道存在就行）

子目录/文件存了什么
objects/所有快照的实际数据（文件内容 + 目录结构）
refs/分支和标签的指针（指向最新的 commit）
HEAD当前你在哪个分支
logs/操作记录（每次 commit、checkout 的时间戳）
index暂存区——购物车的实际存储文件
为什么叫「仓库 (Repository)」而不叫「文件夹」？

因为里面不只有文件本身，还存了整个项目的版本历史。一个 .git 隐藏文件夹 + 工作目录 = 一个仓库。普通文件夹里只有「现在」，仓库里有「现在 + 所有过去」。

三、git add → git commit — 存档分两步

这是 Git 最核心、最容易搞混的设计：保存不是一键完成，而是两步。

git add -A           第一步：把文件放进「暂存区」（购物车）
git commit -m "..."   第二步：给购物车拍一张快照，永久保存

为什么设计成两步？

场景：你在写报告，同时改了三个文件——数据表、分析结论、封面排版。数据表和结论改完了可以存，但封面改到一半还不满意。如果只能一键全存，半成品的封面也被存档了。

有了暂存区，你可以选择哪些文件这次要存档，哪些下次再说：

工作目录
你正在编辑的文件
→ add →
暂存区
购物车·挑选这次要存的
→ commit →
仓库
📸 永久快照
术语严格定义比喻
工作目录 (Working Directory)你在编辑的、看得见摸得着的文件你的办公桌
暂存区 (Staging Area / Index)下一次 commit 将要包含的文件列表，存在 .git/index 里购物车——挑选哪些这次结账
仓库 (Repository)所有已提交快照的集合，存在 .git/objects/ 里存档室——永远可以回去看

commit 里面存了什么？

每次 commit 不是一个「差异文件」，而是一张完整快照 (Snapshot)——当时所有文件的状态。同时附带了：

  • 一个唯一 ID（SHA-1 哈希，如 df30a0e）
  • 你的留言（-m 后面的内容）
  • 时间戳
  • 作者信息
  • 指向上一个 commit 的指针（形成历史链）
commit 是不是像游戏存档？

是，但有重要区别：

游戏存档Git commit
通常只能覆盖永不覆盖——每次 commit 都在旧的基础上追加
存档之间没有关联每个 commit 记录自己的「父 commit」，形成一条链
只有一个存档槽可以有无数个 commit，任意跳转
不能看到「上次存档到现在变了什么」git diff 可以精确显示两版之间的差异

四、git push — 把存档同步到 GitHub

git push -u origin master

commit 只存在你电脑的 .git 文件夹里——GitHub 完全不知情。push 的作用就是把本地的新 commit 发送到远程仓库。

命令要素意思
push把本地的新存档「推」到远程
origin远程仓库的别名，默认指向你 clone 或添加的那个 URL
实际值是 git@github.com:6HOLLIS/yak-meat-report.git
master分支名——主线默认叫 master
-u设置上游 (upstream) 跟踪——让 Git 记住这个对应关系
以后只敲 git push 就够了，不用每次写 origin master

commit 和 push 的关系

commitpush
数据去哪本地 .git/objects/GitHub 服务器
需要联网？不需要需要
别人能看到？不能能（Public 仓库）
频率很频繁——每完成一个小改动就 commit按需——攒几个 commit 后 push 一次
最佳实践：commit 要频繁（每完成一个逻辑单元就存档），push 可以攒一波再推。比如你今天改了 5 次报告，可以 5 个 commit + 1 次 push，GitHub 上会看到 5 个历史记录。

五、SSH 密钥 — GitHub 怎么知道「是你」

基础概念

术语严格定义
SSHSecure Shell，一个网络协议，用于在两台机器之间建立加密连接。不只是 GitHub 用，登录远程服务器、传输文件都走 SSH
密钥对 (Key Pair)一对数学上相关联的文件——私钥和公钥。它们来自同一套数学参数，但私钥推导公钥容易，公钥反推私钥在计算上不可行
非对称加密上面这套机制的名称：「加密和解密用不同的钥匙」——跟「对称加密」（一个密码既加密又解密）相对

私钥 vs 公钥

私钥公钥
在哪你电脑上 ~/.ssh/id_ed25519GitHub 网站（你粘贴的那行）
文件大小411 字节96 字节
谁能看只有你。权限 600（仅文件所有者可读写）公开无所谓，没有任何安全风险
做什么用证明「我是我」——用私钥对一条消息做数字签名验证「你确实是你」——用公钥验证那个签名
泄密后果别人可以冒充你 push 代码、登录服务器零后果

认证过程：挑战-应答 (Challenge-Response)

1. 你的电脑 → GitHub：  「我是 6HOLLIS，我要 push」
2. GitHub → 你的电脑：    「证明一下。用 6HOLLIS 的公钥加密这段随机数：0x8a3f...」
3. 你的电脑 → 用私钥解密 → 发回原文
4. GitHub → 用公钥验证：  「解密结果和我发的随机数一致 → 你确实持有私钥 → 放行」
安全的核心：私钥从未离开你的电脑，密码从未出现在传输中。传输的只是加密后的挑战码——就算被截获，攻击者没有私钥也解不开挑战。这就是为什么 SSH 密钥比用户名密码登录更安全。

Ed25519 是什么

SSH 密钥有三种主流算法。你生成命令里的 -t ed25519 就是指定它：

算法密钥长度速度安全等级
RSA 4096很长的字符串（~800 字符）慢高，但量子计算下有理论弱点
ECDSA较短中中，但依赖高质量的随机数源
Ed25519最短（96 字符）最快最高，抗侧信道攻击

Ed25519 是目前业界推荐的标准，新项目默认用它。

生成命令完整拆解

ssh-keygen -t ed25519 -C "6HOLLIS@github" -f ~/.ssh/id_ed25519 -N ""
参数意思
ssh-keygenSSH 密钥生成工具
-t ed25519算法类型：Ed25519
-C "6HOLLIS@github"注释 (Comment)——不参与加密运算，仅作为标签帮你识别「这是哪把密钥」
-f ~/.ssh/id_ed25519输出文件名
-N ""不设密码短语 (Passphrase)——空字符串。设了的话每次 push 要输密码，更安全但更麻烦

known_hosts：防冒充

ssh-keyscan -t rsa github.com >> ~/.ssh/known_hosts

第一次连接新服务器时，SSH 会弹：「这台机器的指纹是 XX:XX:XX，确实要连接它吗？」。如果攻击者在中间建了一台假服务器（中间人攻击 MITM），指纹就对不上。这行命令提前把 GitHub 的真实公钥写入 known_hosts，告诉 SSH：「我已确认这台机器就是 GitHub，以后不用再问」。

每次 push 需要手动输密钥吗？

不需要，完全自动。git push 触发 → SSH 自动在 ~/.ssh/ 目录找到私钥 → 自动完成挑战-应答认证 → push 成功。整个过程你只感知到那一个命令。

换电脑了怎么办？

新电脑上没有私钥，push 就会报 Permission denied (publickey)。两个选择：

  1. 把旧私钥文件拷到新电脑的 ~/.ssh/ 目录下
  2. 在新电脑上重新生成一对，把新公钥加到 GitHub——旧公钥可以留着（多设备共存），也可以删掉

六、操作一：在 GitHub 上创建仓库

打开 github.com/new，填以下内容：

你填/选的意思
Repository name: yak-meat-report仓库名——会出现在 URL 里
Public公开仓库——任何人可以看，但不能改（除非你邀请）
不勾 Add a README file如果你勾了，GitHub 会先给你建一个带 README 的空仓库。但你的本地项目已经有文件了——两个不同的初始提交会导致「无关历史合并」的问题，解决起来很痛苦

八、操作三：GitHub Pages — 把 HTML 变成网站

打开 github.com/6HOLLIS/yak-meat-report/settings/pages：

设置你的选择意思

你的：
https://6HOLLIS.github.io/yak-meat-report/analysis-report.html
Pages 和普通网站托管有什么区别？

Pages 是静态网站托管——只托管 HTML/CSS/JS 文件，没有后端代码，没有数据库，没有服务器端处理。对于你这样的分析报告页面来说完全够用。如果你以后需要动态功能（用户登录、数据存储），就需要更高级的方案（Vercel、Netlify 或自建服务器）。

九、自动更新机制：完整传导链条

改网站内容的唯一方式：在你电脑上编辑文件 → 走 Git 流程 → push。不能直接在 GitHub 网站上改（那会绕过 Git 的工作流）。

传导链路

1. 你在电脑上编辑 analysis-report.html → 保存 (Ctrl+S)
2. git add -A             → 文件进暂存区
3. git commit -m "..."    → 快照存入本地 .git/objects/
4. git push               → 快照发送到 GitHub 仓库
                                 master 分支的 HEAD 指针向前移动
                                    ↓
5. GitHub 检测到 master 分支发生变化
                                    ↓
6. Pages 自动拉取最新文件，重新部署到 Web 服务器
                                    ↓
7. https://6hollis.github.io/yak-meat-report/analysis-report.html
   指向最新版本（约 30 秒延迟）
关键理解：Pages 不是监听文件变化——它监听的是分支指针变化。你 push 了新 commit，master 分支的指针移到了新 commit，这个事件触发了 Pages 的重新构建。这是一个事件驱动机制，不是轮询。

日常更新就三行命令

git add -A
git commit -m "更新了某某内容"
git push

手动的只有前三行。从 push 成功到网站更新，全自动。

十、git status — 看懂输出

这是你最常跑的命令——随时看看当前什么状态：

git status

On branch master
→ 当前在 master 分支

Your branch is up to date with 'origin/master'.
→ 本地和 GitHub 同步，没有未推送的 commit

Untracked files:
  .playwright-mcp/
→ Git 发现一个它不认识的文件夹——不在版本管理中

nothing added to commit but untracked files present
→ 已跟踪的文件都没改动，但有一个新文件夹需要你决定怎么处理
文件状态含义
Untracked (未跟踪)Git 不认识这个文件——既不存档，也不管它。可能是新建的文件还没 add
Tracked (已跟踪)文件在 Git 管理下。细分三种子状态：
  Modified已修改，尚未 add 到暂存区
  Staged已 add 到暂存区，等 commit
  Committed已存档，干净状态
fatal: not a git repository —— 什么意思？

当前目录（及其所有上级目录）中没有 .git 文件夹——不是在仓库里。你需要先 cd 到项目根目录。只有根目录下面有 .git，子目录里也能跑 git 命令（它会自动向上查找 .git）。

十一、.gitignore — 告诉 Git「这些不用管」

.gitignore 是一个黑名单文件。写在里面的路径，Git 当它们不存在。

.gitignore 示例：
.playwright-mcp/     忽略这个文件夹
*.tmp                忽略所有 .tmp 结尾的文件
node_modules/        忽略依赖包（几万个文件不该上传）
.env                 忽略环境变量文件（含密钥/密码）
.DS_Store            Mac 系统垃圾文件
常见放进 gitignore原因
node_modules/依赖包——体积巨大且可以从 package.json 重建
.env密钥、密码、API Token——绝对不能推送到公开仓库
*.log, *.tmp临时文件和日志——没有版本管理价值
dist/, build/构建产物——可以从源码重新生成
.DS_Store, Thumbs.db操作系统生成的垃圾文件
.gitignore 本身会被推送吗？

会。.gitignore 本身是一个被 Git 跟踪的普通文件——它列出的路径才被忽略。推送 .gitignore 的意义是：让别人克隆你的仓库时也遵守同样的忽略规则。这是一份「项目规则」，不是「本机设置」。

十三、概念词典

术语定义
Repository (仓库)一个被 Git 管理的项目目录，包含工作文件 + .git 版本历史
Commit (提交/快照)一次存档操作的结果——包含当时所有文件的完整快照、留言、时间戳、作者、父 commit 指针
Branch (分支)一条独立的开发线。master 是默认主线。多分支允许同时做多个功能而不互相干扰
Remote (远程)远程仓库的别名。origin 是默认别名，指向你 clone 或添加的 GitHub URL
Clone (克隆)把远程仓库完整复制到本地（包括全部版本历史），用 git clone {URL}
Pull (拉取)把远程的新 commit 下载到本地并合并，用 git pull。多人协作时别人 push 了你需要 pull
Staging Area (暂存区)add 和 commit 之间的中间区域，让你选择性存档
HEAD一个指针，指向当前所在分支的最新 commit
SSHSecure Shell 协议，用于加密网络连接和身份认证
GitHub PagesGitHub 的静态网站托管服务——把仓库里的 HTML 自动变成网站
