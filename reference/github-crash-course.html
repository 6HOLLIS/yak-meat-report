Git & GitHub 速通

从零到发布网站的实战笔记

2026 年 7 月 基于真实操作 零基础友好
背景：本笔记源于一次真实操作——将一份行业分析报告通过 Git 推送到 GitHub，再用 GitHub Pages 发布为公开网站。每一步拆解为「做了什么 + 为什么这样做 + 底层原理」，适合对照学习。

00 起点：你要做什么

假设你有一堆写好的文件（报告、网页、代码），你想：

  1. 记录每次修改的历史，随时能回退到旧版本
  2. 把文件存到云端，换电脑也能继续工作
  3. 生成一个 URL，别人点开就能看

答案是三条工具链串在一起：

Git本地版本管理
→
GitHub远程托管
→
GitHub Pages网站发布

01 Git 和 GitHub 是两样东西

这是最容易混淆的基础概念。先拆开：

GitGitHub
是什么你电脑上的命令行软件一个网站，微软旗下
干什么记录文件版本——时间机器存放 Git 仓库 + 协作 + 部署
需要联网？不需要，完全离线可用需要，它是远程服务器
关系Git 管本地 → git push 推到 GitHub → 代码在云端
所以 GitHub 只是「存代码的网盘」？

远超网盘。网盘只存最新版本，GitHub 存完整的历史记录——每次 commit 的快照都在。你可以查看三年前的代码、对比任意两版差异、多人同时改同一项目不会互相覆盖、用 Pull Request 做代码审查、用 Issues 跟踪 Bug。

GitHub 不是网盘，是协作平台。网盘只是它最基础的功能。

02 git init — 造一台时间机器

git init

在当前文件夹里创建一个隐藏目录 .git。从此刻起，这个文件夹就不再是普通文件夹了——它变成了一个仓库 (Repository)：

操作前操作后
一个普通文件夹，改了文件没有痕迹文件夹变成仓库，每次修改都可存档、可回溯

.git 里有什么？你不用进去翻，但知道结构有助于理解后面的一切：

子目录/文件存了什么
objects/所有快照的实际数据——文件内容 + 目录结构
refs/分支和标签的指针，指向最新的 commit
HEAD当前你在哪个分支
index暂存区——「购物车」在磁盘上的实体
logs/每次操作的时间戳记录
关键认知：普通文件夹只有「现在」，仓库有「现在 + 所有过去」。这就是「版本控制」四个字的物理含义。

03 git add → git commit — 存档分两步

这是 Git 最核心、最容易搞混的设计：保存不是一键完成，而是两步。

git add -A           第一步：文件进暂存区（购物车）
git commit -m "留言"   第二步：给购物车拍永久快照

为什么设计成两步？

你在写报告，同时改了三个文件——数据表、分析结论、封面排版。数据表和结论改完了可以存，但封面改到一半还不满意。如果只能一键全存，半成品的封面也被存档了。

有了暂存区，你可以选择哪些文件这次要存档，哪些下次再说：

工作目录正在编辑的文件
→ add →
暂存区购物车 · 挑选这次要存的
→ commit →
仓库📸 永久快照
术语严格定义类比
工作目录你正在编辑的、看得见摸得着的文件你的办公桌
暂存区 (Index)下一次 commit 将要包含的文件列表，存在 .git/index购物车
仓库 (Repository)所有已提交快照的集合，存在 .git/objects/存档室

commit 里面存了什么？

每次 commit 不是存「跟上一版的差异」，而是一张完整快照 (Snapshot)——当时所有文件的状态，附带：

  • 一个唯一 ID（SHA-1 哈希，如 df30a0e）
  • 你的留言（-m 后面的内容）
  • 时间戳 + 作者信息
  • 指向上一个 commit 的指针——形成一条历史链
commit 是不是像游戏存档？

是，但有两个关键区别：

① 永不覆盖。游戏存档通常只能覆盖旧存档，Git commit 永远在旧的上面追加。你永远可以回到任何一个历史版本。

② 链式结构。每个 commit 记录自己的「父 commit」，形成一条完整的链条。游戏存档之间没有这种关联。

最佳实践：commit 要频繁、颗粒度要细——每完成一个逻辑单元就存档一次。留言写清楚「做了什么」，而不是「什么时候做的」。好的留言让三个月后的你自己也能看懂。

04 git push — 把存档同步到 GitHub

git push -u origin master

commit 只存在你电脑的 .git/objects/ 里——GitHub 完全不知情。push 把本地的新 commit 发送到远程仓库。

命令要素意思
push把本地新存档「推」到远程
origin远程仓库别名，实际值是 git@github.com:6HOLLIS/...
master分支名，主线默认叫 master
-u记住这个对应关系——以后只敲 git push 就够

commit 和 push 的关系

commitpush
数据去哪本地 .git/objects/GitHub 服务器
需要联网？不需要需要
别人能看到？不能能（Public 仓库）
频率频繁——每完成一个小改动就 commit按需——攒几个 commit 后 push 一次

05 SSH 密钥 — GitHub 怎么知道「是你」

基础概念

SSHSecure Shell，一个网络协议，用于在两台机器间建立加密连接。不只是 GitHub 用，登录远程服务器、传输文件都走它
密钥对一对数学上关联的文件——私钥（绝不离身）和公钥（可以公开）。用公钥加密的东西只有私钥能解开
非对称加密加密和解密用不同钥匙——跟「对称加密」（一个密码既加密又解密，如 ZIP 密码）相对

私钥 vs 公钥

私钥公钥
在哪你电脑上 ~/.ssh/id_ed25519GitHub 网站上（你粘贴的那行）
文件大小~400 字节~100 字节
谁能看只有你。权限设为 600公开无所谓，无安全风险
做什么证明「我是我」——做数字签名验证「你确实是你」——验证签名
泄密后果别人可冒充你 push 代码零后果

认证过程：挑战-应答

1. 你的电脑 → GitHub：  "我是 6HOLLIS，我要 push"
2. GitHub → 你的电脑：  "证明一下。用 6HOLLIS 的公钥加密这段随机数：0x8a3f..."
3. 你的电脑 → 私钥解密 → 发回原文
4. GitHub → 公钥验证： "解密结果和我发的随机数一致 → 你确实持有私钥 → 放行"
安全的核心：私钥从未离开你的电脑，密码从未出现在传输中。传输的只是加密后的挑战码——就算被截获，攻击者没有私钥解不开。这就是为什么 SSH 密钥比用户名密码登录安全得多。

Ed25519 是什么

你生成命令里的 -t ed25519 指定了算法类型：

算法密钥长度速度安全等级
RSA 4096~800 字符慢高
ECDSA较短中中
Ed25519最短（96 字符）最快最高，抗侧信道攻击

Ed25519 是目前业界推荐的标准，新项目默认用它。

生成命令完整拆解

ssh-keygen -t ed25519 -C "6HOLLIS@github" -f ~/.ssh/id_ed25519 -N ""
参数意思
ssh-keygenSSH 密钥生成工具
-t ed25519算法类型：Ed25519
-C "6HOLLIS@github"注释 (Comment)——不参与加密，仅作标签帮你识别这是哪把密钥
-f ~/.ssh/id_ed25519输出文件路径
-N ""不设密码短语——空字符串。设了的话每次 push 要输密码

known_hosts：防冒充

ssh-keyscan -t rsa github.com >> ~/.ssh/known_hosts

第一次连接新服务器时 SSH 会问「这台机器指纹是 XX，确定要连接吗？」。这行命令提前把 GitHub 的真实公钥写入 known_hosts，等于「我已确认这台机器确实是 GitHub」——防止中间人冒充。

每次 push 需要手动输密钥吗？

不需要，完全自动。git push 触发 → SSH 自动在 ~/.ssh/ 找到私钥 → 自动完成挑战-应答 → push 成功。整个过程你只感知到那一个命令。

换电脑了怎么办？

新电脑上没有私钥，push 会报 Permission denied (publickey)。两种方案：① 把旧私钥文件拷到新电脑的 ~/.ssh/ 目录；② 在新电脑重新生成一对，把新公钥加到 GitHub。两种方式等价。

06 操作一：在 GitHub 上创建仓库

打开 github.com/new：

你填/选的意思
Repository name: yak-meat-report仓库名——会出现在 URL 里
Public公开仓库——任何人可以看，不能改（除非你邀请）
不勾 Add a README file如果你勾了，GitHub 会先建一个带 README 的空仓库。而你本地已有文件——两个不同的根 commit 会产生「无关历史」冲突，初学者最常卡在这里
不勾 Add .gitignore同上——你的项目已经有 .gitignore 了
⚠️ 常见坑：如果 GitHub 上已有初始 commit（勾了 README），你本地也初始化了 Git——两个仓库的根 commit 不同，push 会报 fatal: refusing to merge unrelated histories。记住：要么 GitHub 先建，clone 下来改；要么本地先建，GitHub 上空仓接。二者不可混。

07 操作二：添加 SSH 公钥

打开 github.com/settings/keys：

你选/填的意思
Key type: Authentication Key用途是身份认证。GitHub 还支持 Signing Key——给你的 commit 做数字签名防冒名提交，那是进阶用法
Title: 我的Windows电脑一个标签。以后换电脑或密钥丢了，你能认出这条是哪个设备的
Key: 粘贴公钥内容把 ~/.ssh/id_ed25519.pub 原样粘贴。GitHub 存下后，任何持有对应私钥的人就能以你的身份操作仓库

08 操作三：GitHub Pages — 把 HTML 变成网站

打开 github.com/6HOLLIS/yak-meat-report/settings/pages：

设置你的选择意思
SourceDeploy from a branch从分支直接部署——GitHub 读取你分支上的文件当作网站发布
Branchmaster从哪个分支读文件
Folder/ (root)从哪个子目录读——选根目录即整个仓库都发布

URL 规则

https://{用户名}.github.io/{仓库名}/{文件路径}
Pages 是静态网站托管——只托管 HTML/CSS/JS 文件，没有后端、没有数据库。对于文档和报告页面完全够用。如果需要动态功能（登录、数据存储），以后可以用 Vercel 或自建服务器。

09 自动更新机制：完整传导链条

改网站内容的唯一方式：在你电脑上编辑文件 → 走 Git 流程 → push。

1. 编辑文件 → 保存 (Ctrl+S)
2. git add -A             → 文件进暂存区
3. git commit -m "..."    → 快照存入本地 .git/objects/
4. git push               → 快照发送到 GitHub
                              → master 分支 HEAD 指针前移
5. GitHub 检测到分支变化        → 触发 Pages 重新构建
6. 约 30 秒后 → 网站指向最新版本
Pages 不是轮询文件变化——它监听的是分支指针变化。你 push 了新 commit，master 指针移到新位置，这个事件触发构建。这是一个事件驱动机制。

日常更新就是三行命令

git add -A
git commit -m "更新了某某内容"
git push

手动的只有前三行。push 之后全自动。

10 git status — 看懂每一行输出

这是你最常跑的命令——随时查看当前状态：

git status

On branch master                              ← 当前在 master 分支
Your branch is up to date with 'origin/master'. ← 本地和 GitHub 同步

Untracked files:                                ← Git 发现了不认识的文件
  .playwright-mcp/                               ← 不在版本管理中

nothing added to commit but untracked files present
                                                  ← 已跟踪文件无改动，但有个新文件夹需要处理

文件的三种追踪状态

状态含义
UntrackedGit 不认识——新建文件尚未 add
Modified已跟踪，但内容已改动，尚未 add 到暂存区
Staged已 add 到暂存区，等待 commit
Committed已存档，干净状态
fatal: not a git repository — 什么意思？

当前目录（及其所有上级目录）中没有 .git 文件夹——你不在一个仓库里。需要先 cd 到项目根目录。只有根目录下有 .git；在子目录里也能跑 git 命令，它会自动向上查找。

11 .gitignore — 告诉 Git「这些不用管」

.gitignore 是一个黑名单文件。写在里面的路径，Git 当它们不存在。

.gitignore 示例：
.playwright-mcp/     忽略这个文件夹
*.tmp                忽略所有 .tmp 结尾的文件
node_modules/        依赖包——几万个文件，不应上传
.env                 🔴 密钥/密码——绝对不能推到公开仓库
.gitignore 本身会被推送吗？

会。.gitignore 本身是一个被 Git 跟踪的普通文件——它里面列出的路径才被忽略。推送它意味着让其他 clone 你仓库的人也遵守同样的忽略规则。这是一份「项目规则」，不是「本机设置」。

13 概念词典

Repository仓库——一个被 Git 管理的项目目录，包含工作文件 + .git 版本历史
Commit提交/快照——一次存档操作的结果，含完整文件快照、留言、时间戳、父 commit 指针
Branch分支——一条独立的开发线。master 是默认主线
Remote远程——远程仓库的别名。origin 指向 GitHub URL
Clone克隆——把远程仓库完整复制到本地（包括全部版本历史），用 git clone {URL}
Pull拉取——把远程的新 commit 下载到本地并合并，用 git pull
Staging Area暂存区——add 和 commit 之间的中间区域，选择性存档
HEAD一个指针，指向当前所在分支的最新 commit
SSHSecure Shell 协议，用于加密网络连接和身份认证
GitHub PagesGitHub 的静态网站托管服务——仓库里的 HTML 自动变成网站
